# 1.1 人像变焦修复与大头贴核对

日期：2026-10-17。设备：小米 17 Pro Max / popsicle，HyperOS OS4.0.4.0.XPBCNXM。当前基础移植模块 Leica camera 0.225 / build225，移植相机 6.6.000570.5。本补丁版本 1.1；人像修复初版 versionCode 14，清理与硬件识别版 versionCode 15。

## 原因与修改

在独立完整背屏相机的人像模式复现：当前为 2× 时，点击原生倍率按钮请求 5×，但人像 ZoomManager 的范围为 0.7–2×，因此请求被拒绝，反复点击仍停在 2×。

旧补丁恢复了本机 `S6` Smart FOV 能力，却没有恢复配套的 `w1` 倍率表。移植配置的 `w1` 返回 null，原生代码退回通用镜头档位，出现按钮档位和模式范围不一致。

1.1 在原有本机能力恢复列表中仅增加 `w1`，背屏时调用 APK 自带的 Popsicle 配置方法。人像档位恢复为 0.7、1、1.2、1.5、2×。未设置新的点击监听器、未更换变焦控制器、未放宽人像最大倍率，主屏仍沿用原有配置。

系统原厂 6.7.000280.0 从当前系统 product 分区临时只读挂载提取；提取后已经卸载该临时挂载。其 Popsicle `L1` 人像表与移植 APK 内 Popsicle `w1` 一致，原生倍率选择与 Smart FOV 分支对应。没有替换手机上的相机 APK，也没有切回原厂环境运行 UI。本轮原厂结论来自代码对照，运行验证在现有移植环境完成。

## 实机验证

- 人像完整点击循环：1 → 1.2 → 1.5 → 2 → 0.7 → 1×；2× 后正常回到 0.7×。
- 日志确认 `PortraitZoomManager` 实际应用对应倍率，原生界面、画面取景范围与倍率标签同步。
- 大头贴点击循环：1 → 2 → 5 → 0.7 → 1×。保留原生通用镜头档位与循环算法。
- 大头贴长按显示原生刻度滑轴，拖动产生 0.9、0.8× 等连续倍率，日志确认 `action=3` 并下发到相机。
- 拍照、人像、大头贴之间切换正常；从大头贴返回人像恢复人像自己的倍率表。
- 相机进程重启后再次完成以上人像循环，确认新补丁加载。最终另以 1.1 名称构建、覆盖安装并检查版本及加载日志。
- 构建与 APK 签名验证通过，`git diff --check` 通过。本轮未重新验证拍摄保存、水印或完整四连拍。

证据保存在本机 `stock-camera-study/zoom-*` 的截图、运行日志及反编译对照文件中，不纳入公开图片资源。没有清除相机数据、修改 LSPosed 作用域或改动基础移植模块。

## 清理与硬件识别

Device Faker 当前将 `com.android.camera` 包括在 `device=nezha` 的身份模板中；基础适配器读取这个身份后，其背屏分支记录 `REAR_SKIP physical rear menu device=nezha`。本次不修改用户的伪装配置，在附加补丁中改用 DisplayManager 枚举真实内置副屏及物理分辨率。应用 attach 后、相机活动启动前安装背屏 hook，避免在没有 Context 时猜测设备身份。

17 Pro 的 904×572 背屏对应 APK 自带 `Pandora` 配置，Pro Max 的 976×596 背屏对应 `Popsicle` 配置；横竖方向归一化，不固定副屏 ID。仅内置非主屏可匹配，HDMI、无线投屏、虚拟显示和未知面板不匹配。17 Pro 官方参数参见 [小米官网](https://www.mi.com/prod/xiaomi-17-pro/specs)。两套原厂配置类均在受支持的移植 APK 中核对存在；17 Pro 的 `S6/w1` 已静态核对，尚未在 17 Pro 真机验证。

删除旧 `d0/e0` 监听器屏蔽、`DEBUG/dump()` 和未使用的 `leica` 字段，仍执行原生提供器初始化。若基础适配器已创建带原有标记的 ESP 按钮，不再额外创建第二个；菜单标签复用适配器的已调整标记，避免两边重复加间距。

本机覆盖安装后日志为 `HARDWARE rear=1 panel=976x596 profile=popsicle reportedDevice=nezha`，并有 `READY 1.1`。人像五档往返、大头贴四档点击及原生长按滑轴通过，无本轮 `REAR_HOOK_ERROR`。纯 Java 测试覆盖两款面板、旋转、非固定 ID、主屏排除、HDMI/投屏/虚拟屏排除及未知面板排除，共 10 项通过。主屏按钮有安装日志；本轮主屏 UI 回归受锁屏限制，不计为已完成。未切换 Device Faker 配置测试基础适配器同时启用的情形。
